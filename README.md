# onetime

Минималистичное веб-приложение для передачи секретных данных (текста и файлов)
по **одноразовой ссылке**.

Зачем: при пересылке пароля или других секретов мессенджером автоматические
предпросмотры ссылок («предпросмотрщики») открывают ссылку и портят данные.
Одноразовая ссылка показывает данные ровно один раз; если кто-то открыл её
первым, об этом узнают — страница показывает, кто просматривал (дата/время,
IP-адрес, User-Agent).

## Как это работает

| Роль | Что происходит |
| --- | --- |
| Отправитель | Заходит на сайт, вводит текст в поле, прикладывает файлы (опционально) и нажимает «отправить». Получает ссылку вида `https://<домен>/<UUID>` и кнопку «Скопировать» |
| Получатель | Открывает ссылку и сначала видит подтверждение: чекбокс и кнопку «Просмотреть». После подтверждения показывается сообщение и вложения; в БД сохраняются время просмотра, IP и User-Agent, ссылка помечается просмотренной |
| Получатель (повторно) | Видит предупреждение, что ссылка уже была просмотрена, и данные о том, кто смотрел. Если это были не он — ссылка скомпрометирована, нужно связаться с отправителем |

Маршруты:

- `/` — форма (GET) и создание ссылки (POST);
- `/done/<UUID>` — страница отправителя: готовая ссылка и кнопка «Скопировать»
  (не затрагивает состояние ссылки);
- `/<UUID>` — страница получателя: GET — подтверждение (до просмотра) или
  «уже просмотрено» (после); POST — показ данных и фиксация просмотра;
- `/<UUID>/f/<id>` — скачивание вложения, доступно только после того, как
  однократный просмотр уже потреблён.

Ссылки генерируются из `base_url` конфигурации либо из запроса
(схема + заголовок `Host`), поэтому при развёртывании на собственном домене
они автоматически выглядят как `https://<домен>/<UUID>`.

## Требования

- PHP ≥ 8.1 с расширением `pdo_mysql`;
- MariaDB ≥ 10.6 (или MySQL 8);
- веб-сервер, умеющий маршрутизировать запросы во фронт-контроллер
  (пример для Nginx — в `deploy/nginx.conf.example`).

## Установка

1. Создайте базу данных и пользователя, примените схему:

   ```sql
   CREATE DATABASE onetime CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'onetime'@'localhost' IDENTIFIED BY '<пароль>';
   GRANT ALL PRIVILEGES ON onetime.* TO 'onetime'@'localhost';
   ```

   ```sh
   mysql -u root onetime < sql/schema.sql
   ```

2. Настройте приложение:

   ```sh
   cp config/config.example.php config/config.php
   # укажите DSN, пользователя и пароль БД, при желании — base_url
   ```

   Файл `config/config.php` в git не попадает (`.gitignore`).

3. Направьте веб-сервер в `public/` (см. `deploy/nginx.conf.example`).

4. Для вложений согласуйте лимиты: PHP (`upload_max_filesize`,
   `post_max_size`), приложение (`limits` в `config/config.php`) и
   `max_allowed_packet` MariaDB — содержимое файлов хранится в LONGBLOB.

## Лимиты (значения по умолчанию)

- до 10 вложений, до 16 МБ каждое (настраивается в `config/config.php`);
- сообщение — произвольный текст (`MEDIUMTEXT`);
- имя файла — до 255 символов, User-Agent в БД — до 512.

## Примечания о безопасности

Это пет-проект, а не система обмена секретами:

- данные хранятся в БД в открытом виде — защищайте и делайте резервные копии
  базы;
- аутентификации нет, управление доступом — только «знаешь UUID»;
- просмотр фиксируется в момент подтверждения (чекбокс + «Просмотреть»);
- вложения не отдаются, пока однократный просмотр не потреблён: бот
  предпросмотра не может украсть файл, не «сгоревшая» ссылка его не раскрывает;
- кнопка копирования использует Clipboard API (требует HTTPS), для
  незащищённого контекста есть запасной путь через `document.execCommand`;
- ссылок нет механизма истечения срока и удаления — можно добавить.

## Структура

- `public/` — фронт-контроллер (`index.php`) и статика (`assets/`);
- `src/` — логика (`app.php`) и представления (`views.php`);
- `sql/schema.sql` — схема БД (идемпотентная, можно применять повторно);
- `config/config.example.php` — пример конфигурации;
- `deploy/nginx.conf.example` — пример vhost Nginx.

Коммиты — Conventional Commits. Написано ИИ агентом.
