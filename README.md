# onetime

Минималистичное веб-приложение для передачи секретных данных (текста и файлов)
по **одноразовой ссылке**.

Зачем: передать пароль или другие секреты по ссылке так, чтобы данные были
показаны ровно один раз. Если кто-то открыл ссылку раньше получателя, об этом
узнают — страница показывает, кто просматривал (дата/время, IP-адрес,
User-Agent).

## Как это работает

| Роль | Что происходит |
| --- | --- |
| Отправитель | Заходит на сайт, вводит текст в поле, прикладывает файлы (опционально), при желании задаёт пароль (опционально) и нажимает «отправить». Получает ссылку вида `https://<домен>/<UUID>` и кнопку «Скопировать» |
| Получатель | Открывает ссылку и сначала видит подтверждение: чекбокс и кнопку «Просмотреть» (плюс поле пароля, если отправитель его задал). После подтверждения показывается сообщение и вложения; в БД сохраняются время просмотра, IP и User-Agent, ссылка помечается просмотренной |
| Получатель (повторно) | Видит предупреждение, что ссылка уже была просмотрена, и данные о том, кто смотрел. Если это были не он — ссылка скомпрометирована, нужно связаться с отправителем |

Маршруты:

- `/` — форма (GET) и создание ссылки (POST);
- `/done/<UUID>` — страница отправителя: готовая ссылка и кнопка «Скопировать»
  (не затрагивает состояние ссылки);
- `/<UUID>` — страница получателя: GET — подтверждение (до просмотра; с полем
  пароля, если он задан) или «уже просмотрено» (после); POST — проверка
  пароля (если задан), показ данных и фиксация просмотра;
- `/<UUID>/f/<id>` — скачивание вложения, доступно только после того, как
  однократный просмотр уже потреблён.

Ссылки генерируются из `base_url` конфигурации либо из запроса
(схема + заголовок `Host`), поэтому при развёртывании на собственном домене
они автоматически выглядят как `https://<домен>/<UUID>`.

## Требования

- PHP ≥ 8.1 с расширением `pdo_mysql`;
- MariaDB ≥ 10.6 (или MySQL 8);
- веб-сервер, умеющий маршрутизировать запросы во фронт-контроллер
  (пример для Nginx — в `deploy/nginx.conf.example`).

## Установка

1. Создайте базу данных и пользователя, примените схему:

   ```sql
   CREATE DATABASE onetime CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'onetime'@'localhost' IDENTIFIED BY '<пароль>';
   GRANT ALL PRIVILEGES ON onetime.* TO 'onetime'@'localhost';
   ```

   ```sh
   mysql -u root onetime < sql/schema.sql
   ```

   Если база создавалась до появления опционального пароля (защита ссылки),
   примените миграцию — она добавит колонку `password_hash`:
   
   ```sh
   mysql -u root onetime < sql/migrations/2026-11-20-add-password-hash.sql
   ```

2. Настройте приложение:

   ```sh
   cp config/config.example.php config/config.php
   # укажите DSN, пользователя и пароль БД, при желании — base_url
   ```

   Файл `config/config.php` в git не попадает (`.gitignore`).

3. Направьте веб-сервер в `public/` (см. `deploy/nginx.conf.example`).

4. Для вложений согласуйте лимиты: PHP (`upload_max_filesize`,
   `post_max_size`), приложение (`limits` в `config/config.php`) и
   `max_allowed_packet` MariaDB — содержимое файлов хранится в LONGBLOB.

5. Настройте cron-очистку устаревших данных (см. `purge` в
   `config/config.php`), чтобы вложения и журналы не накапливались:

   ```sh
   # /etc/cron.d/onetime — ежедневная очистка в 03:17
   17 3 * * * root /usr/bin/php /var/www/onetime/tools/purge_old.php >> /var/log/onetime-purge.log 2>&1
   ```

## Лимиты (значения по умолчанию)

- до 10 вложений; фактический лимит размера — минимум из
  `limits.max_file_bytes` в `config/config.php` (по умолчанию 16 МБ),
  `upload_max_filesize`/`post_max_size` PHP и `max_allowed_packet` БД:
  вычисляется автоматически и показывается в форме; `client_max_body_size`
  Nginx из PHP невидим — держите его не меньше вычисленного значения
  (см. `deploy/nginx.conf.example`);
- сообщение — произвольный текст (`MEDIUMTEXT`);
- пароль (опционально) — от 8 до 128 символов;
- имя файла — до 255 символов, User-Agent в БД — до 512.

## Примечания о безопасности

Это пет-проект, а не система обмена секретами:

- данные в БД: текст сообщения и хеш пароля стираются из БД **сразу при
  просмотре** (тем же UPDATE, что фиксирует `viewed_at`); вложения (файлы)
  остаются в БД, пока их не уберёт cron-очистка (см. ниже), — защищайте и
  делайте резервные копии базы с учётом этого;
- аутентификации нет, управление доступом — только «знаешь UUID»;
- опциональный пароль хранится в БД только как bcrypt-хеш
  (`password_hash()`), в открытом виде нигде не записывается; сам пароль
  рекомендуется передавать получателю отдельным каналом;
- попытки ввода пароля не ограничены по частоте (нет rate-limit);
- просмотр фиксируется в момент подтверждения (чекбокс + «Просмотреть»);
- вложения не отдаются, пока однократный просмотр не потреблён: до этого
  запрос к файлу просто получает «не найдено»;
- каждая успешная отдача вложения записывается в журнал
  (`download_log`: ссылка, файл, IP, User-Agent, время) — по нему видно,
  сколько раз файл реально скачали (в т.ч. повторные запросы после обрыва);
- кнопка копирования использует Clipboard API (требует HTTPS), для
  незащищённого контекста есть запасной путь через `document.execCommand`;
- устаревшие данные убирает cron-задача `tools/purge_old.php`: просмотренные
  ссылки удаляются через `purge.viewed_after_days` (по умолчанию 30 дней)
  после просмотра, не открывавшиеся — через `purge.unviewed_after_days`
  (14 дней) после создания; вместе со ссылкой каскадно удаляются её вложения
  и записи журнала скачиваний. Пример cron — в конце раздела «Установка»;

## Структура

- `public/` — фронт-контроллер (`index.php`) и статика (`assets/`);
- `src/` — логика (`app.php`) и представления (`views.php`);
- `sql/schema.sql` — схема БД (идемпотентная, можно применять повторно);
- `sql/migrations/` — одноразовые миграции для существующих баз;
- `tools/purge_old.php` — cron-скрипт очистки устаревших ссылок/вложений;
- `config/config.example.php` — пример конфигурации;
- `deploy/nginx.conf.example` — пример vhost Nginx.

Коммиты — Conventional Commits. Написано ИИ агентом.
